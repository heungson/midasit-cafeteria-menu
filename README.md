# 구내식당 메뉴 (macOS 메뉴 막대 · Windows 알림 영역 앱)

메뉴 막대(macOS)나 알림 영역(Windows)의 아이콘을 한 번 누르면 **한국 시간 기준 오늘**의 아침·점심·건강존·저녁 메뉴와 배식 시간, 층별 식사시간을 한글 텍스트로 보여 주는 Electron 앱입니다. 사내 그룹웨어 게시판에 매주 올라오는 주간 메뉴표 이미지를 읽어 구조화하고, 결과를 주 단위로 기기에 저장합니다.

> **TL;DR** — `npm ci && npm run build:native && npm test`로 검증하고, `npm run demo`로 데모를 봅니다. 실제 사용에는 관리자에게 받은 **접속 프로필(JSON)** 과 그룹웨어 계정이 필요하며, 사내망 또는 VPN에 연결되어 있어야 합니다.

---

## 동작 방식

1. **로그인** — 접속 프로필에 적힌 로그인 화면과 같은 방식으로 아이디를 만들고(조직 도메인 조회 포함) 폼을 제출합니다. 쿠키는 메모리에만 둡니다.
2. **이번 주 게시물 찾기** — 게시판 목록에서 제목의 기간 `(M/D~ M/D)`가 이번 주(월요일 기준)인 글을 고릅니다. 같은 주 글이 여러 개면 가장 최근 글을 씁니다.
3. **메뉴 이미지 받기** — 게시물 래퍼 → 본문 프레임 → 에디터 본문 → PNG 순으로 따라갑니다. HTML·스크립트는 **실행하지 않고** 문자열로만 해석하며, **같은 출처**의 주소만 요청하고, 삭제·저장 같은 위험한 경로는 건너뜁니다.
4. **이미지 구조화**
   - 표의 파란 격자선을 찾아 **날짜 열 × 식사 행**으로 자릅니다(손으로 그린 듯 흔들리는 선도 묶어서 인식).
   - **Claude Code CLI**에 날짜마다 `머리글 1장 + 식사 칸 4장`을 이미지 블록으로 직접 보내고 `--json-schema`로 출력 형식을 강제합니다. 받은 결과는 앱에서 한 번 더 스키마 검증합니다.
   - Claude가 실패한 날짜만 **macOS Vision** 또는 **Windows 한국어 OCR**로 다시 읽습니다. 기본 OCR이 있으면 Claude 결과와 대조해 일치율이 낮을 때 경고합니다.
5. **날짜 검증** — 열의 날짜 머리글을 게시 기간과 맞춰 봅니다. 맞지 않는 열은 버리고, **다른 날·다른 주의 메뉴를 오늘 것으로 보여주지 않습니다.**
6. **캐시와 변경 감지** — 결과를 주 단위로 저장하고(원본 이미지는 저장하지 않고 SHA-256만 보관), 확인 간격마다 게시물과 이미지 해시를 다시 확인해 바뀌었을 때만 다시 인식합니다.

### 화면에 표시하는 상태

| 상태 | 표시 |
|---|---|
| 정상 | 오늘 메뉴(현재 식사 시간대 강조), 배식 시간, 층별 식사시간 |
| 주말 | 주말 안내. 다음 주 게시물이 있으면 날짜를 눌러 미리보기 |
| 미게시 | 이번 주 글 없음 + 최근 게시 기간 |
| 네트워크 단절 | 사내망/VPN 안내. 이번 주 캐시가 있으면 함께 표시 |
| 계정 없음 / 암호 오류 / 없는 사용자 | 설정 열기 버튼. 틀린 비밀번호로는 **자동 재시도하지 않음**(계정 잠김 방지) |
| 추가 인증 필요 | OTP 등 추가 인증 계정은 자동 로그인 미지원 안내 |
| 인식 실패 / 이미지 없음 | Claude·기본 OCR 각각의 실패 사유 |
| 날짜 확인 불가 / 오늘 열 없음 | 메뉴를 표시하지 않음 |

## 준비물

| 항목 | 설명 |
|---|---|
| Node.js 22 이상 | 개발·빌드용 (설치된 앱에는 필요 없음) |
| Claude Code CLI | 권장 인식 엔진. `claude` 명령이 로그인되어 있어야 함. 없으면 기본 OCR만 사용 |
| macOS 13 이상 | Vision 한국어 인식. 도우미 빌드에 Xcode 명령줄 도구 필요 |
| Windows 10/11 | 한국어 OCR을 쓰려면 `설정 > 시간 및 언어 > 언어`에서 한국어 추가 |
| 사내망 또는 VPN | 그룹웨어 접속 |

## 명령어

```bash
npm ci                    # 의존성 설치
npm run build:native      # macOS Vision OCR 도우미 빌드(build/native/mac/vision-ocr, macOS 전용)
npm test                  # 단위·통합 테스트(가짜 그룹웨어, 합성 메뉴표, 실제 OS OCR 포함)
npm start                 # 개발 실행(메뉴 막대/알림 영역에 아이콘)
npm run demo              # 오프라인 데모(합성 데이터를 이번 주 날짜로 옮겨 표시)
npm run fixtures          # 합성 메뉴표 PNG·데모 데이터·아이콘 다시 만들기
npm run pack:mac          # macOS 패키지(dmg/zip, arm64) + 패키지 검사
npm run pack:win          # Windows 설치 파일(NSIS, x64) + 패키지 검사 (Windows에서 실행)
```

> VS Code 같은 Electron 기반 터미널에서는 `ELECTRON_RUN_AS_NODE=1`이 설정되어 있을 수 있습니다. 앱이 Node처럼 실행되면 `env -u ELECTRON_RUN_AS_NODE npm start`로 실행하세요.

## 접속 프로필 설정

회사별 접속 정보(그룹웨어 주소, 로그인·게시판 경로, 게시판 ID, 폼 필드 이름, 오류 코드, 제목 키워드 등)는 **공개 저장소에 두지 않습니다.** 앱은 다음 순서로 프로필을 찾습니다.

1. 환경 변수 `CAFETERIA_PROFILE`이 가리키는 파일
2. 사용자 데이터 폴더의 `profile.json` — **설치된 앱은 이것만 사용**
   - macOS: `~/Library/Application Support/CafeteriaMenu/profile.json`
   - Windows: `%APPDATA%\CafeteriaMenu\profile.json`
3. (개발 실행만) 저장소의 `profile.local.json` — `.gitignore`에 포함

형식은 [`profile.example.json`](profile.example.json)을 참고하세요(자리표시자만 들어 있음). `{input}`은 사용자가 입력한 아이디, `{loginId}`는 도메인까지 붙인 아이디, `{password}`는 비밀번호로 바뀝니다. `baseUrl`은 `https`여야 합니다.

### 설치된 앱에 프로필 넣기

- **앱에서**: 아이콘 클릭 → ⚙ 설정 → `프로필 파일 가져오기…` → 관리자에게 받은 JSON 선택
- **명령으로**(저장소가 있는 기기): `npm run profile:install -- /경로/프로필.json` (인자를 생략하면 `profile.local.json`)

프로필 파일은 사내 채널로만 전달하고, 공개 저장소·이슈·배포 파일에 넣지 마세요.

### 프로필 점검(계정 불필요)

```bash
npm run verify:live       # 로그인 화면의 폼 필드·제출 경로·도메인 조회, 로그인 전 세션 만료 감지를 실제 서버와 대조
```

## 계정과 개인정보

- 아이디와 비밀번호는 **macOS 키체인 / Windows 자격 증명 관리자에만** 저장합니다(`@napi-rs/keyring`). 설정 파일·캐시·로그에는 남기지 않습니다.
- 자격 증명 항목은 그룹웨어 **호스트별**로 나뉘어, 프로필 주소가 바뀌어도 다른 서버로 계정이 전송되지 않습니다.
- Claude CLI는 도구·MCP·설정 파일을 모두 끈 상태(`--tools ""`, `--strict-mcp-config`, `--setting-sources ""`)로 빈 임시 폴더에서 실행되며, **잘라낸 메뉴 이미지만** 받습니다. 계정·쿠키·그룹웨어 주소·앱 환경 변수는 전달하지 않습니다.
- 메뉴 이미지는 Claude(Anthropic API)로 전송됩니다. 사내 정책상 허용되지 않으면 설정에서 `Claude Code CLI로 인식`을 끄고 기본 OCR만 사용하세요.
- 캐시에는 인식 결과와 원본 해시만 저장하며 최근 6주만 보관합니다.

| Claude 호출 | 가짜 CLI로 인자(스키마·도구 끔)·이미지 블록·환경 변수 미전달·스키마 위반 거부 확인 |

### 실제 이미지 검증(로컬 전용)

실제 메뉴 이미지와 기대값은 git에 올리지 않는 `local/acceptance.json`에 둡니다(형식은 [`scripts/verify-real.js`](scripts/verify-real.js) 머리말 참고).

```bash
npm run verify:real -- --engine both --out local/result.json   # Claude·기본 OCR 각각으로 인식 후 기대값 비교
npm run verify:e2e                                               # 가짜 그룹웨어에 실제 이미지를 올려 앱 서비스 전체 경로 실행
npm run verify:leaks                                             # 공개 대상 파일 비공개 정보 검사
env -u ELECTRON_RUN_AS_NODE npx electron . --demo-data local/result.json --date YYYY-MM-DD --screenshot local/screenshots/today.png
```

## 패키징과 배포

- `npm run pack:mac` → `dist/cafeteria-menu-<버전>-mac-arm64.dmg|zip`. 서명은 ad-hoc이며 공증하지 않았습니다. 다른 기기에서 처음 열 때 Gatekeeper 경고가 나오면 Finder에서 우클릭 → 열기.
- `npm run pack:win` → `dist/cafeteria-menu-<버전>-win-x64.exe` (NSIS, 사용자 단위 설치, 서명 없음).
- 배포 파일에는 `src/`, `assets/`, 합성 데모 데이터만 들어갑니다. `npm run verify:package`가 로컬 프로필·검증 자산·테스트·기기 경로·회사 접속 정보가 빠졌는지 확인합니다.
- 번들 이름은 `CafeteriaMenu`(ASCII)입니다. 한글 번들 이름은 Electron 도우미 앱 탐색 문제로 시작 시 종료되어 표시 이름(`CFBundleDisplayName`)만 한글로 둡니다.

### CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml)은 macOS·Windows에서 테스트 → 패키징 → 패키지 검사 → 패키지 실행(데모 화면 캡처)을 수행합니다. Windows에서는 한국어 OCR 기능 설치를 시도하고, 없으면 해당 테스트만 건너뜁니다. 프로필·실제 이미지가 없으므로 CI는 합성 데이터만 사용합니다.

## 제한 사항

- **실제 계정 로그인은 검증하지 못했습니다.** 계정 없이 확인 가능한 범위(폼 필드, 제출 경로, 도메인 조회, 세션 만료 감지)만 실제 서버와 대조했습니다. 로그인 성공 후 화면, 게시판 목록 HTML 형식, 본문 프레임·에디터 저장 형태는 관찰된 정보와 일반적인 형태(속성·스크립트 문자열·이스케이프된 textarea·hidden input·JS 변수)를 모두 지원하도록 만들었지만 실제 응답으로 확인이 필요합니다.
- 이 그룹웨어는 조직 도메인 조회 결과가 비어 있어, **이메일 주소 전체**를 아이디로 입력해야 합니다(로그인 화면 안내와 같음).
- **추가 인증(OTP 등)** 계정은 감지해 안내만 하며 자동 로그인은 지원하지 않습니다.
- **Windows는 실행해 보지 못했습니다.** 자격 증명 관리자·Windows OCR·알림 영역 동작은 CI 설정만 준비되어 있습니다. Windows 한국어 OCR의 띄어쓰기·정확도도 미검증입니다.
- Claude 인식 정확도는 한 주 분량의 실제 이미지로만 확인했습니다. 메뉴표 양식이 크게 바뀌면(격자선 색·열 수 변화) 격자 분할이 실패할 수 있으며, 이때는 `인식 실패`로 표시됩니다. 날짜 열이 5개가 아니면 머리글 날짜를 읽어서만 날짜를 정합니다.
- 기본 OCR 단독 결과는 줄바꿈된 긴 메뉴 이름이 두 항목으로 나뉠 수 있습니다(서로 다른 메뉴를 합치는 것보다 안전한 쪽을 택함).
- macOS 패키지는 arm64만 로컬에서 만들었습니다. Intel Mac용은 Intel 환경 또는 CI에서 빌드해야 합니다(키링 네이티브 모듈이 아키텍처별).
- 건강존은 표에 별도 배식 시간이 없어 시간을 표시하지 않습니다.
